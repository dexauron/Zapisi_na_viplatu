# Аудит «Сверки» — 20 ноября 2026

Исходная версия: `dexauron/Zapisi_na_viplatu`, `main`, `c908accd3bfa036aac89e2a195df8cc0bdcae61e`.
Изменения подготовлены в ветке `codex/payout-handover-audit-20261118`.

## Новое поведение

1. Положительный связанный расходный кассовый ордер 1С устанавливает **«Деньги отложены»**.
2. Запись остаётся активной у администратора, в личном кабинете и по общей ссылке независимо от прошедшей даты.
3. Только активный администратор отдельной командой подтверждает **«Деньги выданы»**. Сервер сохраняет время и автора.
4. Повторный импорт, возврат товара, банковский платёж и нулевой остаток по накладной не подтверждают выдачу наличных.
5. История выданного фильтруется по фактической дате выдачи. Первоначальная дата записи сохраняется отдельно.
6. Сумма «Ожидают выдачи» включает весь остаток активных записей; «Деньги отложены» показывает часть этой суммы, подтверждённую РКО. Эти показатели не нужно складывать.

## Границы и оставшаяся проверка рабочего проекта

- Полная проверка настроек Auth, всех рабочих документов и всех журналов не проводилась. Проверены затрагиваемые данные, ограничения, функции, права и рекомендации базы.
- Проверки поведения DOM не выдаются за проверку настоящих iPhone/Android. Локальный запуск Chromium ограничен средой; проверка опубликованного интерфейса выполняется отдельно после выкладки.
- Нагрузочный тест на рабочем сервисе не проводился. Ночная выгрузка по-прежнему не заменяет полный бэкап PostgreSQL и Auth.
- Подтверждение выдачи относится ко **всей сумме записи**. Частичная подготовка учитывается; отдельного процесса частичной фактической выдачи этот пакет не вводит.
- Исторические «Оплачено» не переоткрываются автоматически: прежняя схема не сохраняла надёжный источник отметки. У старых записей без автора выдачи и подтверждения представителя показывается пояснение для ручной сверки. Массовое переоткрытие может привести к повторной передаче денег.
- Ограничения конечности добавляются с `NOT VALID`: новые и изменяемые строки защищены, старые некорректные суммы при их наличии требуют отдельной проверки и исправления по документам.
