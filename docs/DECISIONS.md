# Решения

| Дата | Решение | Почему |
|---|---|---|
| 2026-10-30 | Без интеграции с 1С | Решение владельца |
| 2026-10-30 | Supabase (Postgres + Auth) + статичный сайт на GitHub Pages | Бесплатно; нужен общий доступ сотрудников и ТП с разных устройств |
| 2026-10-30 | Интерфейс без сборки (HTML/JS, supabase-js в `vendor/`) | Решение не сложнее задачи; нет зависимостей от npm при выкладке |
| 2026-10-30 | ТП входит по персональной ссылке `index.html#<токен>` | Без паролей для ТП; токен 144 бита, во фрагменте URL (не в логах и Referer); замена ссылки отзывает старую |
| 2026-10-30 | Токены ТП — отдельная таблица `rep_access`, только админ | Сотрудник не должен видеть выплаты через чужую ссылку |
| 2026-10-30 | Роли `admin` / `employee` в `staff`; учётки — Edge Function `staff-admin` | Ключ сервиса не попадает в браузер; сотрудник входит по логину без email |
| 2026-10-30 | Сотрудник: заказы (создать/изменить/отметить), справочники (добавить). Удаление и выплаты — только админ | Минимум прав для работы магазина |
| 2026-10-30 | «Просрочен» вычисляется, не хранится | Нет рассинхронизации статуса с датой |
| 2026-10-30 | Адрес и ключ проекта — переменные GitHub, не код | Как в CRM-Auron: смена проекта без правки кода |
| 2026-10-30 | ~~Проект Supabase в `us-east-1`~~ | Заменено ниже |
| 2026-10-30 | Переезд в `eu-central-1` (Франкфурт), проект `umwystttvkrgentkddik` | Ближе к Грозному: меньше задержка каждого запроса. Перенос сервер-сервер, пароли и ссылки ТП сохранены. Настоящие персональные данные (152-ФЗ) хранить нельзя |
| 2026-10-30 | «Ещё» → «Открыть» помечает ссылку `?from=app`, и на странице появляется «Назад» | Приложение на телефоне идёт без адресной строки: открыв общую ссылку, владелец оставался без выхода. По ссылке из WhatsApp метки нет — представителю возвращаться некуда |
| 2026-10-30 | «Ещё» убрано из нижних вкладок в кнопку с тремя чёрточками справа вверху | Пожелание владельца; внизу остаётся только ежедневная работа, настройки не занимают место |
| 2026-10-31 | Акт сверки — PDF в браузере (jsPDF 4.2.1, MIT; шрифт PT Sans, OFL) | Настоящий PDF на iPhone, Android и ПК без сервера; «Поделиться» отправляет файл в WhatsApp. Грузится только при первом акте |
| 2026-10-31 | «Получил» ставит только представитель по своей ссылке | Подтверждение от второй стороны; сотрудник поставить не может (триггер) |
| 2026-10-31 | Учётки ТП (логин и пароль) — по желанию, рядом со ссылкой | Пожелание владельца. ТП видит только своё через `my_rep_data()`; таблицы закрыты RLS, учётки пишет только `staff-admin` |
| 2026-10-31 | Удаление документов 1С — полное (не пометка), за период и по видам | «Без копий в базе». Ручные записи и заказы не удаляются, только теряют связь; повторная загрузка возвращает документы |
| 2026-10-31 | Несколько накладных → несколько записей, а не одна общая | У каждой накладной своя сумма и номер; сверка с 1С и «Оплачено по 1С» остаются точными |
| 2026-11-05 | Оформление «тетрадь сверок»: Onest, прохладная бумага, чернильно-синий; один яркий элемент — «Чек дня» | Запрос «премиум». Шрифт свой (не системный) — одинаково на iPhone, Android и ПК; хранится в `vendor/`, без внешних сервисов (работа без VPN) |
| 2026-11-05 | «Сводка» считается на сервере (`summary_stats`), выплаты недели — из уже загруженных записей | Документов 1С десятки тысяч: в браузер не тянем; записи на выплату и так в памяти |
| 2026-11-05 | Цвета графика проверены валидатором палитры (светлая и тёмная тема) | Различимы при нарушениях цветового зрения; подписи и таблица (Excel) дублируют цвет |
| 2026-11-16 | Офлайн-очередь привязана к проекту и учётной записи. На поддерживающих браузерах очередь между вкладками обрабатывается через Web Locks | Смена сессии не должна отправлять изменения от имени следующего сотрудника |
| 2026-11-16 | Новая запись выплаты связывается с одной действующей приходной накладной того же поставщика. Автосверка связывает однозначные пары | Не создавать новую двойную запись. Исторические привязки сохраняются для сверки с 1С |
| 2026-11-16 | Причины возвратов и списаний хранятся как снимки регистра по виду и периоду. Доступ только у администратора | В выгрузке регистра строки агрегированы по товарам и причинам, без номера документа. Долг продолжает считаться по движениям 1С |
| 2026-11-20 | РКО означает «Деньги отложены», фактическая выдача — отдельный `set_payout_paid` с автором, временем, блокировкой и версией | Пожелание владельца: закрытие дня в 1С не означает передачу конверта торговому |
| 2026-11-20 | Резерв — часть суммы ожидающих выдачи; частичный РКО хранится отдельной суммой. История — по дате выдачи в московском времени | Не смешивать подготовленную сумму, плановую дату и состоявшуюся передачу денег |
| 2026-11-20 | Исторические оплаты не переоткрываются автоматически; старые офлайн-отметки и удаления сохраняются для ручной проверки | Прежние данные не позволяют надёжно установить факт выдачи; повторная передача денег недопустима |
| 2026-11-20 | Тесты DOM используют JSDOM с закреплённым lock-файлом в `tests/`; сайт остаётся без сборки и новых runtime-зависимостей | Проверять общую ссылку и оба кабинета в CI без обращения к рабочим данным |
| 2026-11-20 | Прежние связи с чужой или отменённой накладной снимаются отдельной миграцией; сама выплата, номер и подтверждённая выдача сохраняются, автоподбор блокируется до проверки | В рабочей базе обнаружена такая связь; нельзя показывать движение другого поставщика или подбирать замену догадкой |

| 2026-11-23 | Один типизированный поиск без внешнего сервиса: имена, компании, номера, деньги, телефоны, даты | Разные правила для имён и цифр; общая логика всех экранов, отсутствие подписки и передачи запросов в сторонний ИИ |
| 2026-11-23 | Опечатки допустимы только в словах; деньги сравниваются в копейках, цифры номера не исправляются | Ошибка в номере или копейке не должна подбирать чужую финансовую запись |
| 2026-11-23 | Архив ищется новым RPC с серверной проверкой роли, лимитами и дешёвым предварительным числовым отбором | Не тянуть десятки тысяч накладных в браузер; не нормализовать каждый номер дорого на каждый запрос |
| 2026-11-23 | Во время поиска порядок определяется релевантностью; обычный список сохраняет даты и компании | Старые точные совпадения не теряются под новыми частичными |
| 2026-11-23 | PostgreSQL + Auth остаются общей базой, GitHub — кодом и публикацией | Владелец подтвердил одновременную работу и личные кабинеты; файлы прайса каталога не обеспечивают транзакции и права выплат |
