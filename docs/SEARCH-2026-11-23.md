# Поиск и интерфейс «Сверки» — 23 ноября 2026

Поиск теперь различает ФИО, названия компаний, номера и суммы. Точные совпадения стоят выше похожих. Он работает по сохранённым данным без сети и дополняет результат архивом 1С при доступном интернете. Фактическая выдача денег остаётся отдельным действием администратора.

## Что мешало находить записи

| Причина | Исправление |
| --- | --- |
| Все поля превращались в общую строку; цифры суммы и номера теряли смысл | Типизированные поля; деньги в копейках, отдельные правила номера |
| Поиск накладной знал только начало входящего номера и полный номер 1С | Новый архивный RPC: номер целиком/частично, сумма, поставщик и сочетания |
| «Сегодня» не подгружал давние записи | Общая загрузка истории, явные состояния загрузки/ошибки/работы без сети |
| Даты и дерево компаний пересортировывали уже найденное | При поиске плоский ранжированный список; обычный режим сохраняет группировку |
| Ранее выбранный статус мог скрывать результат | Новый запрос снимает прежний фильтр статуса; итоги считаются по найденному |
| Медленный ответ мог перезаписать новый поиск | AbortController, номер запроса и проверка актуального контейнера |
| Успешная загрузка истории не сбрасывалась при смене учётки | Владелец запроса, поколение диапазона, граница в кэше и стабильная пагинация по дате + id |
| Связанная выплата повторялась ниже как накладная | Исключение уже показанных документов, открытие существующей записи |
| Подсветка после «№» смещалась из-за Unicode NFKC | Карта исходных позиций, экранирование пользовательского текста |
| Поиск общей ссылки не учитывал сумму | Общий движок с теми же денежными правилами |

## Проверяемые примеры

| Ввод | Поведение |
| --- | --- |
| `Иванов Иван`, `Иванов И. П.`, `И. П. Иванов` | Полное имя, произвольный порядок слов, инициалы до/после фамилии |
| `ИП Петров`, `индивидуальный предприниматель Петров` | Организационная форма и имя компании |
| `Ivanov`, `Bdfyjd`, `Иванво` | Транслитерация, английская раскладка, ограниченная опечатка |
| `12345`, `ПФ-00012345`, `PF12345` | Номер с префиксом/ведущими нулями; точный выше частичного |
| `15000,50`, `15 000,50`, `15 000,50 ₽`, `15.000,50` | Одна сумма 15 000 рублей 50 копеек; 15 000,51 не подходит |
| `Иванов 15000,50` | Должны совпасть и имя, и сумма |
| `+7 (900) 123-45-67`, `8 900 123 45 67` | Вставленный телефон справочника без ручного удаления разделителей |

Опечатки применяются к словам от четырёх букв, максимум две — для длинных слов. Цифры не получают допуска на замену, перестановку или пропуск. Литеральный поиск, транслитерация и раскладка проверяются прежде дорогого разбора опечаток. Все слова запроса обязательны; слабый хвост отсекается относительно лучшего результата. Запрос ограничен 160 знаками, восемью числовыми частями и двенадцатью словами.

## Интерфейс

Одна подписанная кнопка создания на рабочей вкладке вместо повторяющегося плюса. Поиск 48 px с доступным названием, очисткой, Enter, Escape и Ctrl/Cmd+K. В результатах длинные имена и номера переносятся. Резерв и выдача подписаны явно. На телефоне итоги стоят строками, на компьютере — колонками; сохранились Onest, светлая/тёмная темы и боковая навигация. Поиск не добавляет быстрого подтверждения выдачи в архив накладных.

## Проверки и границы

- 54 модульных теста: распознавание имён/сумм/номеров, отрицательные примеры, Unicode, HTML, прежний интерфейс поиска и прежние финансовые правила.
- 66 проверок настоящих HTML/JS в JSDOM: 38 прежних и 28 новых. Проверены приоритет старого точного номера, дозагрузка истории, снятие фильтра, устаревшие ответы, повтор после ошибки, отсутствие изменения денег, личный кабинет и общий график. JSDOM не проверяет CSS.
- Чистый PostgreSQL 18.6: 22 миграции, 84 прежних проверки прав + 30 выдачи + 31 поиска, таблиц public без RLS нет. Пять проверок гонки двух соединений; сохранность старой оплаты и исправление прежних неверных связей.
- Рабочий PostgreSQL 17.11: новая миграция применена и зарегистрирована; 31 новый сценарий с откатом прошёл. Контрольная сумма всех выплат до/после совпала.
- Deno 2.9.7: линтер; проверка типов неизменённой копии функции с официальным SDK 2.119.2, установленным через npm. Прямая загрузка пакета из Deno в этой среде недоступна; CI проверяет исходную команду.
- Реальная отрисовка в Chromium через штатный предпросмотр: 320, 390 и 1280 px, вымышленные записи. Настоящие финансовые действия в рабочем приложении не выполнялись. Физические iPhone/Android и экранный диктор не проверены.
- Локальный PostgreSQL, 40 000 вымышленных накладных: сумма 4 мс; цифровой номер 98 мс; номер с кириллицей 87 мс; транслитерация 94 мс; отсутствие номера 94 мс. Это время локального запроса, без сети и гарантий скорости рабочей базы.
- Прогретый клиентский поиск на 6 000 вымышленных строках: обычные запросы 9–42 мс; запрос с опечаткой 80–177 мс. Производительность слабого телефона может отличаться.

Без сети показан только сохранённый набор. Архив 1С требует соединения. В кабинете представителя поиск ограничен тем, что вернул его существующий API (включая установленный период документов), и не даёт доступа к чужим сведениям. Архивный ответ ограничен 200 накладными; дальше предлагается уточнить запрос.

## На что опирались

Из каталога Way Market использованы принципы раздельного поиска чисел и текста, весов полей, двух проходов и отсечения слабых результатов. Архив каталога не изменялся.

Изучены первичные описания: [Google — смысл запроса и релевантность](https://www.google.com/intl/en_us/search/howsearchworks/how-search-works/ranking-results/), [Яндекс — исправление опечаток](https://yandex.ru/support/search/ru/troubleshooting/replace.html), [Meilisearch — настройка опечаток и отключение для чисел](https://www.meilisearch.com/blog/typo-tolerance). Реализованы подходящие приёмы для финансового справочника, без внешнего поискового сервера и сторонней ИИ-подписки.

## Где хранятся данные

Пользователь подтвердил общую работу сотрудников и личные кабинеты. Код и публикация остаются в GitHub; рабочие данные — PostgreSQL + Auth. Каталог раздаёт через GitHub файлы прайса, тогда как выплаты требуют прав по ролям, блокировок и проверки версий. GitHub поддерживает [статический хостинг](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), а его [API изменения файлов](https://docs.github.com/en/rest/repos/contents) не заменяет такую модель доступа. В репозитории уже есть workflow шифрованных резервных копий; его настройка и успешный ночной запуск в рамках этой доработки не подтверждались. Рабочие данные в публичный репозиторий не выгружались.
